# Deck brief interview

Use this branch only when the user asks to be interviewed, grilled, challenged, or guided through
the brief.

## Light interview

1. Start with a short recap of facts already established from the request, supplied sources, and
   relevant repository files. Distinguish facts from assumptions.
2. Ask one unanswered decision question at a time. Include a recommended answer and one sentence
   explaining why it fits the known context. Wait for the answer before continuing.
3. Prioritize audience, desired audience action, single takeaway, strongest evidence, and tone or
   constraints—in that order, skipping anything already known.
4. Default to at most three questions. Stop earlier when the brief is actionable or the user says
   it is enough.
5. Summarize the agreed brief and ask for confirmation before creating the deck.

## Deep interview

Continue beyond three questions only when the user explicitly asks for a deep interview or a
relentless stress test. Walk one branch at a time through narrative, objections, evidence gaps,
slide-level structure, visual language, and delivery constraints. Resolve repository facts through
inspection; reserve questions for decisions only. Do not create the deck until the user confirms
the shared brief.
